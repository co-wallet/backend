# Контракт парсера Monefy

Пакет `internal/importer/monefy` предназначен для API предпросмотра и импорта.
Он принимает один автономный SQLite `.db` с `user_version = 11`, возвращает
нормализованный `Report` и не обращается к PostgreSQL или сети.

```go
report, err := monefy.Parse(ctx, upload, monefy.Options{
    SupportedCurrencies: []string{"RUB", "USD", "EUR", "TRY"},
})
```

`upload` — `io.Reader`. Список валют передаётся из актуального серверного
каталога, а не из клиентского запроса. Пустой список — ошибка конфигурации.
HTTP-обработчик должен ограничивать размер и время чтения тела запроса.
Отмена контекста проверяется между чтениями; пакет не может прервать
заблокированный `Read` произвольного пользовательского reader.

## Результат и допуск к импорту

При `err != nil` импорт запрещён. Ошибка `*monefy.Error` содержит стабильный
`Code`, имя сущности, исходный ID и причину; поддерживает `errors.As` и
`errors.Is`. Частичный отчёт содержит блокирующее сообщение `parse_failed`.
Не передавайте низкоуровневую причину ошибки SQLite напрямую пользователю.

При `err == nil` отчёт может содержать три вида диагностик:

| Severity | Значение для API |
| --- | --- |
| `warning` | Информация, например отключённый счёт с сохранённой историей |
| `confirmation` | Живая запись исключена из-за ссылки на удалённую сущность; требуется явное подтверждение |
| `blocking` | Данные нельзя импортировать до устранения причины |

`Report.CanImport()` возвращает `true` только при отсутствии блокировок
и неподтверждённых исключений. Парсер сам не принимает подтверждения.
API может разрешить перечисленные `Exclusions` только после подтверждения
конкретного предпросмотра, связанного с точным содержимым загруженного файла.
Подтверждение исключений не снимает `blocking`.

Срезы результата могут быть `nil`; HTTP DTO при необходимости преобразует их
в пустые массивы. Доменные структуры не имеют JSON-тегов.
`Deleted` содержит количество удалённых записей по таблицам; отсутствующий
ключ означает ноль. `Exclusions` содержит сущность, исходный ID и причину
исключения каждой живой записи. Записи с несуществующими ссылками отдельно
обозначены блокирующей диагностикой с исходным ID.

## Соответствие полей

| Источник | Результат |
| --- | --- |
| `Account.Id`, `Name`, `Icon`, `CurrencyId` | Исходные идентификаторы, имя, иконка и валюта счёта |
| `Account.CreatedOn` | `CreatedAt` — дата начального остатка |
| `Account.InitialBalanceCents` | `InitialBalance`, точные тысячные, включая отрицательный остаток |
| `Account.IsIncludedInTotalBalance` | `IncludedInTotal`, исходный флаг без автоматического преобразования в `kind` |
| `Account.DisabledOn` | `DisabledAt`; счёт и история остаются в отчёте |
| `Category.CategoryType` | `0 → income`, `1 → expense`; других значений нет |
| `Category.DisabledOn` | `DisabledAt`; категория сохраняется |
| `Transaction.Id`, `AccountId`, `CategoryId`, `Note` | Идентификаторы и описание без дедупликации |
| `Transaction.AmountCents` | `Amount`: положительный доход, отрицательный расход |
| `Transfer.AmountCents` | Положительная `FromAmount`, сумма списания |
| `Transfer.AccountFromId`, `AccountToId` | Исходные счета перевода |
| `Currency` | Полный исходный каталог, включая код, ID, имя, символ, `MinorUnits`, `IsBase` |
| `CurrencyRate` | Все неудалённые исторические курсы и исходные ID |

Все денежные значения `Amount` — целое `int64` в тысячных единицы валюты:
`12345 → 12.345`. `Amount.String()` возвращает точную десятичную строку.
`MinorUnits` не меняет масштаб и не даёт оснований округлять историю до копеек.
Начальные остатки находятся в счетах, а не добавляются повторно как доходы.
Нулевые обычные операции сохраняются; отрицательные исходные `AmountCents`
операций и неположительные суммы переводов считаются некорректными.

Даты — .NET ticks: 100 нс от `0001-01-01`, допустимы годы 1–9999. Результат
представлен `time.Time` в UTC с сохранением всех ticks. UTC здесь фиксирует
исходные календарные поля: источник не содержит часового пояса, поэтому
нельзя дополнительно сдвигать дату по локальному поясу сервера.

Записи не схлопываются по сумме, дате или описанию. Повторный `Id` внутри
таблицы — ошибка. Идентификаторы разных таблиц имеют отдельные пространства.
Пустые категории и счета без операций также сохраняются.

## Исторические валютные переводы

Для одинаковой валюты `ToAmount = FromAmount`. Для разных валют:

1. Выбираются неудалённые **прямые** курсы нужной пары с
   `RateDate <= Transfer.CreatedOn`.
2. Берётся максимальная `RateDate`, затем максимальная `CreatedOn` среди
   исправлений этой даты. Время создания исправления может быть позже перевода.
3. Если у последних исправлений одинаковые обе даты, но разные значения,
   перевод блокируется. Одинаковые значения допустимы.
4. `ToAmount = trunc(FromAmount * RateCents / 1000000)` в тысячных единицы
   валюты. Произведение вычисляется через `big.Int`, без промежуточного overflow
   и без float. Поскольку суммы положительны, усечение совпадает с floor.

Например, `FromAmount = 1234567` и `RateCents = 333333` дают `411521`
тысячную, то есть `411.521`. Округление до ближайшей тысячной здесь неверно.
При нулевом результате или выходе за `int64` перевод блокируется.

`Transfer.RateID` указывает применённый курс. Если сумму нельзя установить,
`ToAmount == nil` и есть блокировка `ambiguous_rate` или `amount_range`.
Обратные курсы, цепочки через базовую валюту и сетевые курсы не подставляются:
их соответствие алгоритму источника не подтверждено. Файл, которому нужен
такой алгоритм, требует отдельного исследования.

Выбор последнего исправления, масштаб 1 000 000 и усечение подтверждены
полной локальной сверкой 10 межвалютных переводов с CSV-эталоном, включая
несколько исправлений курса на одну дату. Совпадают также 2557 обычных
операций, обе стороны всех 273 переводов и 13 начальных остатков.
Это проверка исследованной версии экспорта, а не гарантия для других версий.

## Ограничения и диагностика

| Code | Причина |
| --- | --- |
| `configuration` | Не задан список разрешённых валют |
| `io`, `format`, `version`, `schema` | Ошибка чтения, повреждение, неподдерживаемая версия или отсутствующая структура |
| `data`, `limit`, `timeout` | Некорректное значение, превышение лимита или отмена обработки |
| `unknown_currency` | Валюта живого счёта отсутствует в источнике или каталоге сервера |
| `invalid_reference` | Не найден счёт, категория или валюта курса; некорректная пара курса |
| `deleted_reference` | Исключённая живая запись со ссылкой на удалённую сущность |
| `disabled_account` | История отключённого счёта сохранена |
| `ambiguous_rate`, `amount_range` | Нельзя надёжно восстановить сумму зачисления |
| `unsupported_schedule`, `unsupported_setting` | Расписание, связь операции с расписанием или настройка требуют отдельной поддержки |
| `unsupported_schema`, `unsupported_column` | Неизвестный объект схемы или поле |

Файл ограничен 64 MiB, суммарное число строк — 100000, включая удалённые,
текстовое поле — 64 KiB, обработка — контекстом до 15 секунд. SQLite также
ограничивает длину строки записи и SQL до 128 KiB; большие записи получают
диагностируемую ошибку. BLOB, REAL, неверный UTF-8, NUL в тексте, некорректные
флаги и даты отклоняются. Технические поля `LocalHashCode`, `RemoteHashCode`
и индексы игнорируются.

Парсер создаёт приватную временную копию, проверяет заголовок, версию,
целостность SQLite и схему. Соединение использует `mode=ro`, `immutable=1`,
`query_only` и отключённый `trusted_schema`. Копия удаляется при успехе и ошибке.
WAL-базы отклоняются: нужен самостоятельный экспорт, содержащий всё состояние
в одном файле. Исходный файл и рабочая БД не изменяются.

Удалённые сущности, операции, переводы, курсы и расписания исключаются.
Непустые живые расписания и настройки блокируют импорт, поскольку молча
отбрасывать их нельзя. Иконки и флаги сохраняются в исходном виде; выбор
иконок приложения, типов счетов, права доступа, подбор свободных имён счетов,
сопоставление общих категорий и запись данных относятся к вызывающему API.
При интеграции нельзя преобразовывать `Amount` в существующие DTO с
`float64`: нужен точный путь записи десятичных значений.

## Проверки

Обычные тесты создают базы из `testdata/v11.sql` в `t.TempDir()`. Фикстура
полностью синтетическая; реальные выгрузки не хранятся в репозитории.

```sh
rtk go test ./internal/importer/monefy -race -cover
```

`TestLocalReference` дополнительно запускается при заданных переменных
`MONEFY_REFERENCE_DB` и `MONEFY_REFERENCE_CSV` с путями к локальным эталонам.
Он сравнивает мультимножества записей, включая повторные операции, и проверяет
неизменность SHA-256 исходной БД. Вывод содержит только счётчики.
CSV используется исключительно как локальный тестовый эталон и не является входом парсера.

### Сквозная проверка API

`TestMonefyAPIEndToEnd` в `internal/repository` проверяет реальные HTTP handlers,
JWT middleware, сервисы и PostgreSQL: preview, выбор типов, согласие с исключениями,
confirm, повтор confirm, чтение счетов, категорий, операций и долей. Ожидаемые
балансы заданы независимо от preview. Фикстура состоит из `testdata/v11.sql`
и применяемого после него `testdata/api.sql`. Она включает две валюты, два
одинаковых расхода, исторический межвалютный перевод с усечением, неиспользованную
категорию, отключённый счёт и исключаемую операцию удалённого счёта.

Для запуска нужна **отдельная тестовая PostgreSQL**, не рабочая БД приложения.
Тесты создают собственные схемы, применяют миграции и удаляют только свои схемы
при завершении. Запускайте из корня backend, задав локально
`MONEFY_TEST_DATABASE_URL`:

```sh
rtk go test ./internal/repository -run TestMonefy -race -count=1
```

Для генерации файла браузерной проверки во временном каталоге из корня backend:

```sh
rtk proxy python3 - <<'PY'
import sqlite3
import tempfile
from pathlib import Path

folder = Path(tempfile.mkdtemp(prefix='cowallet-monefy-'))
path = folder / 'synthetic.db'
with sqlite3.connect(path) as connection:
    for name in ('v11.sql', 'api.sql'):
        connection.executescript(
            Path('internal/importer/monefy/testdata', name).read_text()
        )
print(path)
PY
```

Загрузите полученный файл в пустую тестовую учётную запись dev-стека с валютой
TRY в каталоге сервера. Для Cash выберите текущий тип, Travel — накопительный,
Reserve — инвестиционный. Проверьте preview: Cash −3728.391 RUB, Travel
1412.520 TRY, Reserve 1234.567 RUB; затем примите одно исключение и подтвердите.
В истории за 2024 год должны быть три обычные операции и два перевода.

`TestMonefyAPILocalReference` дополнительно требует `MONEFY_REFERENCE_DB` и
`MONEFY_REFERENCE_CSV`. Он импортирует локальную базу через API в отдельную
схему и сопоставляет с CSV балансы каждого счёта и суммы по валюте/типу операции,
включая обе стороны переводов и начальные остатки. Сравнение выполняется точными
рациональными числами без округления; проверяется SHA-256 **обоих** источников.
Вместе с `TestLocalReference` это проверяет и мультимножество исходной истории,
и результат записи/чтения. Тесты без локальных переменных явно пропускаются.
Пути и файлы задаются только локально; в git и отчёты не включаются личные
операции, имена счетов и реальные суммы. Отчёт теста содержит только счётчики.
