# AGENTS.md

Инструкции по работе с backend-репозиторием **co-wallet**.

## Назначение и стек

Go API приложения для учёта личных и семейных финансов.

- Go 1.25, chi, pgx/v5, goose, PostgreSQL 16.
- Путь модуля: `github.com/co-wallet/backend`.
- `cmd/server/main.go` отвечает за lifecycle и сборку зависимостей.
- `cmd/server/router.go` содержит маршруты и HTTP middleware.

## Команды

```bash
make run          # локальный запуск на :8080
make restart      # перезапуск и проверка /api/health
make stop         # остановка локального backend
make build        # сборка bin/server
make test         # go test ./... -race
make lint         # golangci-lint run ./...
make generate     # выполнить все go:generate, включая mockgen
make mock         # явная перегенерация всех gomock-файлов
make migrate      # применить миграции; нужен DATABASE_URL
make migrate-down # откатить одну миграцию
```

## Архитектура

Соблюдать направление зависимостей `handler -> service -> repository`.

- Handler занимается только HTTP: decode, validation, вызов сервиса, response.
- Бизнес-правила, проверки доступа и оркестрация нескольких операций находятся в service.
- Handler зависит от узкого интерфейса сервиса и не обращается к repository напрямую.
- Repository принимает и возвращает доменные значения, а не HTTP request DTO.
- Многошаговые атомарные операции выполнять через `db.WithTx`.
- Доменные модели не содержат JSON-тегов. Response DTO определяются в handler-пакетах.
- Даты вне JSON request boundary представлены только `time.Time` или `*time.Time`.

## Ключевые правила предметной области

- Каждая транзакция хранит строки в `transaction_shares`, включая личные счета. Аналитика использует эти строки для расчёта пользовательской доли.
- Изменение участников и долей счёта не меняет исторические транзакции.
- Аналитика конвертирует суммы через USD: `amount * rate(USD->display) / rate(USD->native)`.
- Курсы загружаются из `open.er-api.com` при старте и затем каждые два часа.
- Регистрация доступна только по приглашениям; публичного `/api/auth/register` нет.
- Access JWT живёт 15 минут, refresh JWT — 30 дней. Тип токена обязателен в claims; access и refresh нельзя взаимозаменять.
- Счета и категории удаляются мягко. Транзакции и теги удаляются жёстко с очисткой связей.

## Ошибки

- Использовать sentinel-ошибки из `internal/apperr` и проверять их через `errors.Is`/`errors.As`.
- Не сравнивать ошибки по тексту.
- Добавлять контекст через `fmt.Errorf("контекст: %w", err)`.
- Не оставлять `_ = err` без русского комментария, объясняющего, почему ошибку нельзя обработать.
- При нескольких независимых ошибках, например основной и rollback, использовать `errors.Join`.

## Тесты

- Тесты обязательны для каждого изменения поведения.
- Публичные методы сервисов тестировать через testify suite и gomock.
- Для чистой логики и validation использовать table-driven тесты.
- Проверять happy path, validation, not-found, conflict и authorization сценарии.
- Моки генерируются из интерфейсов; не редактировать generated-файлы вручную.

Перед публикацией PR выполнить `make test`, `make lint` и `make generate` по необходимости.

## Локальная разработка в Docker

При запущенном dev-стеке обычные изменения `.go` подхватывает Air: пересборка образа и ручной перезапуск контейнера не нужны.

- После изменения `go.mod` или `go.sum` выполнить `make deps-backend` в репозитории Docker-конфигурации.
- После добавления или изменения миграции выполнить там же `make restart-backend`: миграции применяются при старте backend.
- После изменения переменных окружения выполнить `make recreate-backend`.
- После изменения dev Dockerfile или версии Go выполнить `make rebuild-backend`.
- Полная пересборка обязательна для production-образа и deployment-конфигурации, но не для обычной правки исходников.
